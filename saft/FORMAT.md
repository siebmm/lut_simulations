# Bring a different model and its velocity histories

The reusable workflow accepts **homogeneous, isotropic 2D elastic specimens**.
The finite-element solver and model-file format are independent of SAFT: export
the geometry, acquisition metadata and velocity histories described here.
COMSOL is not required to read or reconstruct them.

Run a complete synthetic example first:

```sh
python tools/make_example.py --output output/example_dataset
python tools/validate_dataset.py output/example_dataset
python tools/analyze.py --dataset output/example_dataset --request output/example_dataset/analysis.json --output output/example_analysis
```

Build the four native tools before the last command. Choose empty output folders.
The example has a sloping outer boundary, a rectangular void, seven sources,
thirteen receivers, 2,401 samples, a 20 ns interval and a -2 µs start time. Its
synthetic point scatterer is at x = 3 mm, z = 12 mm. It is an analytic test signal,
not an independent finite-element simulation or an experimental validation.

## Files to supply

```text
my_dataset/
  dataset.json       # name and relative paths to the two definitions
  geometry.json      # material, boundary polygons, optional reflected paths
  acquisition.json   # sources, receivers, sampling, cases and recording paths
  histories/
    shot0_measurement_vz.csv
    ...
```

Copy the three editable definitions in [examples/general_2d](examples/general_2d).
The CSVs are generated by `make_example.py`; they are not duplicated in Git.
Machine-readable structural definitions are in [schema/](schema/). The validator
also checks cross-file consistency, polygon topology and the actual CSV values.
Paths must stay inside the dataset, including symlink resolution, and use forward
slashes. Different datasets can have different counts, extents, cases and timing.

`dataset.json`:

```json
{
  "schema": 2,
  "kind": "SAFT acquisition dataset",
  "name": "My specimen",
  "geometry": "geometry.json",
  "acquisition": "acquisition.json"
}
```

## Geometry and coordinates

All geometry is in **metres**, in a global `(x,z)` coordinate system. There is no
implicit thickness offset or coordinate inversion in schema 2. The plotted z
axis points downward; translated and rotated specimens, including negative
coordinates, are supported. Convert a solver's upward y coordinate and velocity
consistently: for `z = constant - y`, use `vz = -vy`.

`geometry.json` contains:

- `schema: 2` and `coordinate_system: "x_z_m"`.
- `material`: `cl_m_s`, `cs_m_s`, `cr_m_s`, and `rho_kg_m3`. Supply positive
  density and speeds with `cl > cs > cr > 0`. The Rayleigh speed is used for
  nuisance-arrival guides, not as a propagated imaging mode.
- `loops`: one `outer` loop followed by zero or more `hole` loops. Each has
  `vertices_m` and `boundary_ids`, one unique name per edge. The last edge joins
  the last vertex to the first; do not repeat the first vertex. Outer vertices
  have positive signed area in x,z; holes have negative signed area. Inward
  normals therefore point to the left of each directed edge. Loops cannot cross,
  overlap or touch; holes must be inside the outer loop and cannot be nested.
- Optional `paths` and `screening_boundaries`, described below.

Curves can be approximated by polygon segments. The ray solver uses the supplied
segments exactly; convergence of that approximation is the model author's
responsibility. Holes and exterior space exclude both image pixels and ray legs.
Geometry does not need to name a weld or contain a known defect.

## Acquisition and CSV contract

`acquisition.json` contains:

- `schema: 2`, `velocity_units: "m/s"`.
- `sampling`: integer `samples`, positive `dt_s`, and `start_s`. Row `i` has
  `time_s = start_s + i * dt_s`. All supplied histories share this time grid.
  Resample irregular solver output before import; interpolation and anti-aliasing
  must suit the solver's native sampling and the requested bandwidth.
- `filter_half_samples`: positive integer FIR half-width. The analytic Kaiser
  bandpass has `2 * filter_half_samples + 1` coefficients. Complete filter and
  interpolation support are required at each reconstructed arrival. A different
  sample interval also changes the filter's physical duration.
- `response`: either `{"model": "isotropic"}` for unit launch/receive response,
  or `{"model": "laser_free_surface", "line_half_width_m": 0.0005,
  "pulse_fwhm_s": 6.5e-9}` for the existing laser/free-surface response model.
  Isotropic response is an explicit approximation, not an automatic calibration
  for an arbitrary transducer. Raw versus weighted processing remains selectable.
- `sources`: each has a unique string `id`, `position_m: [x,z]`, and `trigger_s`
  in the same absolute time frame as the CSV. One source is active per history.
- `receivers`: each has a unique string `id`, `position_m: [x,z]`, and a named
  `group`. This array defines CSV column order. Counts and group names are not
  fixed. Sources and receivers can be distinct and need not have equal counts.
- `inward_normal: [nx,nz]` on every source and receiver when using laser response.
  This unit vector must match its finite boundary face. Endpoints must lie in the
  interior of that face, away from vertices. With isotropic response, endpoints
  may also lie inside the material, and normals are optional.
- `cases`: arbitrary unique case names, such as `measurement` and `baseline`.
  `difference` is reserved. A baseline is optional.
- `components`: `vx`, `vz`, or both. These are global vector components, in m/s.
  Native weighted reception projects the local free-surface response onto the
  selected global component; it does not assume a horizontal receiving surface.
- Optional `difference: {"minuend": "measurement", "subtrahend": "baseline"}`.
  Difference histories are calculated from this pair, never supplied as extra CSVs.
- `recordings`: exactly one entry for every source × case × component, each with
  `source`, `case`, `component`, and a unique relative `path`.

Identifiers start with an ASCII letter and contain only letters, digits, `_` or
`-`. Use numeric row ordering as declared in the JSON; do not sort labels yourself.

Each CSV is UTF-8, comma-delimited, with exactly one header and one row per sample:

```csv
time_s,sensor0,sensor1,sensor2
-2e-6,0,0,0
-1.98e-6,1.25e-8,-3.8e-9,0
-1.96e-6,1.40e-8,-4.1e-9,2.1e-10
```

This is a format illustration; a complete file must contain `sampling.samples`
rows. The first column must be `time_s`; remaining names must exactly match
the entire receiver list in acquisition order. Values must be finite decimal or
scientific-notation numbers, preferably exported with 17 significant digits.
Missing values, NaN/Inf, comments, blank data rows, extra columns, and duplicate
or nonuniform times are rejected. Units and coordinates do not appear as extra
header rows. The time-grid tolerance is `max(1e-15 s, dt_s * 1e-7)`.

## Paths, response and suppression

Four direct source→pixel→receiver hypotheses are always available:
`1-1_LL`, `1-1_LS`, `1-1_SL`, and `1-1_SS`. L/S changes at the image pixel are
scattering hypotheses; their scattering amplitudes are not modelled.

Reflected paths explicitly name ordered finite faces on each branch. For example:

```json
{
  "id": "bottom_LS_S",
  "source": {"modes": "LS", "boundaries": ["bottom"]},
  "receiver": {"modes": "S", "boundaries": []}
}
```

This launches L, converts to S at `bottom`, reaches the image pixel, then travels
directly as S to the receiver. A branch with N reflections requires N+1 modes;
up to four ordered reflections per branch are supported. The solver minimizes
travel time on the finite faces, checks Snell's law, applies elastic free-surface
reflection coefficients, and rejects blocked, nonconverged, grazing or
corner-ending paths. It does not discover all possible reflection sequences.
Inspect `native/path_catalogue.json` and optional `ray_checks` in `SAFTBatch`.

Direct L/S suppression uses visible straight arrivals. Rayleigh suppression is
available only when both endpoints lie on one straight face. To use the existing
backwall suppression controls, name `screening_boundaries.backwall`; the repeated
backwall–surface–backwall guide also needs `screening_boundaries.surface`.
Missing roles produce an error when those controls are requested. They are never
inferred from the specimen's dimensions.

Weighted laser reception uses the rotated tangential/normal response, normalized
by the sum of the corresponding component maxima projected onto the measurement
axis. This bounds the normalized response; it is not an absolute sensitivity
calibration. Material interfaces, anisotropy, 3D spreading, attenuation, curved
surface-wave propagation and diffraction require different physical models and
are not implemented by this format.

## Analysis, plots and comparisons

`analysis.json` contains a `requests` array. Each request's `selection` chooses a
path, cases, component, source/receiver subsets, grid, filtering, gates and
suppression. Coordinate bounds and spacing in selections use **millimetres**;
frequencies use MHz and mute widths use µs. Sampling stays in SI in the dataset.
The upper filter frequency must be strictly below that dataset's Nyquist limit.

Omitted selections use all sources/receivers, the specimen bounding box, and
dataset-sized coverage defaults. Subsets use zero-based indices into the JSON
arrays. The `groups` boolean array follows first occurrence of each receiver
group. A `points_m` array can replace a grid for targeted numerical comparisons.

`tools/analyze.py` validates inputs, runs the shared native engine and writes:

- `validation.json` with input hashes, and `request.json` with the exact request;
- `native/` with arrays, channel usage, settings, timing and provenance;
- per-request/case PNG images with geometry, source and receiver overlays;
- `summary.json` and `summary.csv` with support and peak measurements.

An optional top-level `regions` object maps names to polygons in **metres**. If
both `target` and `background` are supplied, the summary reports their peak
amplitude contrast in dB. Unsupported/empty regions produce null values. No
target, reference recording, defect geometry, or weld-specific scoring mask is
required. Multiple requests support comparisons and parameter sweeps without
editing the analysis code. All four native exporters accept the same schema-2
dataset; `SAFTFilterStudy` also accepts external complex signal banks with the
dataset's sample and receiver dimensions.

The original schema-1 weld datasets and frozen chapter studies remain regression
fixtures. `reproduce_main.py`, `reproduce_figures.py` and the historical surveys
replay their original scientific questions and expected values. Use the generic
analysis workflow for a new specimen; its results are not compared to unrelated
weld truth or published weld scores.

## Verify changes to the implementation

```sh
python -m unittest discover -s tests -v
python tools/verify_interfaces.py
python studies/laser/src/verify_saft_datasets.py
python tools/reproduce_main.py
```

The general-dataset suite checks all native interfaces, independent filtering
and focusing, converted/specular travel times, rotated weighted reception,
void visibility, larger acquisitions, different sampling and invalid inputs.
